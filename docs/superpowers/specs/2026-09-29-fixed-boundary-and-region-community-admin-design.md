# 固定横店外轮廓与管理后台改版

日期：2026-09-29
状态：待用户审阅

## 目标与边界

高德 AOI 权限未获批。首页使用用户在“横店总览”中手绘并保存的轮廓作为最终横店外轮廓。管理后台取消独立“横店总览”菜单，在一个页面内维护片区和小区。小区详情只维护小区资料，房屋由“出售／租赁房屋”菜单独立维护。展示端与管理端不提供相互跳转按钮；开发时仍可手动访问 `/` 与 `/admin`。展示端后续独立开发，本次只处理轮廓来源和入口按钮，不重做其其他交互。

## 固定轮廓数据

方案比较：继续只存在开发机 SQLite 中最省改动，但新 Windows 安装没有轮廓；写成前端常量能离线显示，但会绕开现有地图 API 并在两端产生两份来源；后端仓库保存版本化 JSON，继续由现有读取 API 提供，是本稿采用的方案。

- 来源为本机 `/Users/chengjie/.hd-property-sales/hdmap.sqlite` 的 `overview_boundary` 表中 `id=hengdian` 的记录。已只读核验：72 个 `[经度, 纬度]` 点，更新时间 `2026-09-28T15:21:42.431Z`，坐标范围为经度 120.247453–120.364698、纬度 29.091154–29.21763。
- 实施时将该记录原样导出为后端仓库中的版本化 JSON 数据文件，并校验点数、数值范围及至少三个有效点。该文件成为整体轮廓的唯一运行时数据来源，交付包必须包含它；部署到新 Windows 机器时无需复制开发机 SQLite 才能显示轮廓。
- `GET /api/map/overview-boundary` 继续返回原有 `{ polygon }` 结构，但读取固定文件。移除整体轮廓编辑入口和对应写入接口。既有 SQLite 行保留作历史数据，不在迁移时删除。
- 展示端和管理端都通过上述接口绘制同一轮廓。地图组件停止请求 `/api/map/hengdian-aoi`，不再因 AOI 权限导致轮廓加载失败；地点搜索和路线服务继续使用高德 Web 服务 Key。
- 片区仍是管理员可绘制、编辑、删除的业务边界，与固定横店外轮廓分开维护。

## 管理后台信息结构

主菜单为“片区／小区”“出售／租赁房屋”“周边设施”“字典列表”，默认进入“片区／小区”。删除“横店总览”菜单及其页面入口。管理后台页头删除“打开展示端”按钮；展示端页头删除“打开管理端”按钮。直输 `/admin` 仍允许本机开发访问，后端已有的局域网管理访问限制保持有效。

“片区／小区”页使用左侧树、右侧地图和按操作出现的详情或表单。左侧树顶部固定两个按钮：“新增片区”“新增小区”；按钮不随树内容滚动。页头原“新增小区”按钮改为“快速操作”，用于打开小区列表弹窗。树根直接列各片区及“废弃小区站”，不再有“启用小区”和“热门小区”根节点。片区下为小区、楼幢、单元、楼层、房间。热门小区在原小区节点上显示标识，不复制到另一棵树。废弃小区站保留批量移回片区和永久删除的现有规则；废弃小区不显示为地图上的有效点位。

树区域有独立的固定高度与纵向滚动。当节点滚出可视区时，在树滚动区域顶部固定展示首个可见节点的完整父级路径，例如“城南 › 玫瑰星城 › 12 幢”。路径随滚动更新，不遮住新增按钮；点击路径中的父级可定位回该节点。展开、收起和数据刷新后重新计算路径，避免显示失效节点。

## 片区、小区与地图交互

- 点击片区节点或地图面，地图聚焦该片区，并在本页侧栏维护名称、颜色与边界，可删除；新增片区从树顶部按钮进入绘制及保存流程。
- 点击小区节点、地图点位或列表结果，地图定位到该小区并打开小区详情弹窗。详情仅展示小区资料，不包含房屋录入、挂牌列表、挂牌状态操作。楼幢到房间的树层级仍用于定位，但房屋数据的新增与编辑进入“出售／租赁房屋”菜单完成。
- 新增小区从树顶部按钮进入右侧表单，地图保持可见并可点击回填经纬度；地点搜索、所属片区校验、热门开关、废弃小区规则沿用现有能力。
- 去掉“启用小区”对应的表格内容区。未选中对象时右侧展示完整地图及有效片区、小区点位；选中片区后地图聚焦，选中小区后显示详情。废弃小区站仍用表格执行批量操作。
- 地图的整体固定轮廓始终可见。片区多边形和小区点位叠加在其上；固定轮廓不参与业务编辑。

## 快速操作与小区统一编辑

页头“快速操作”打开独立小区列表弹窗。第一行是按小区名称、地址模糊搜索，批量转移到所选片区，以及批量废弃。批量动作只作用于勾选的小区；批量转移沿用目标片区边界校验，有任一小区坐标不在目标片区内时整批不更新。弹窗表格展示所有小区，包括废弃小区；横向滚动呈现名称、所属片区、地址、经纬度、交付日期、配套摘要、规划楼幢数、参考出售均价、热门状态、是否显示、关联设施名称等属性。长文本和设施名称可折叠或用提示展示，避免行高失控。每行提供编辑和删除；启用小区的删除移入废弃站，废弃小区的删除为需确认的永久删除。

小区详情与编辑共用同一个小区资料组件，布局参考附件 1。它包含全部现有属性：名称、所属片区、地址、经纬度、交付日期、配套摘要、规划楼幢数、参考出售均价、热门状态、是否显示、关联周边设施；实际已录入楼幢数作为只读统计。附件 1 中分散的“保存小区资料”和“保存关联设施”合并为一个“保存小区”按钮。新增和编辑均通过一次请求保存主表与设施关联；后端在一个 SQLite 事务中校验片区、多选设施并更新全部资料，失败时不产生部分修改。原有的热门切换、资料更新、设施关联分散写入入口不再由新界面调用。

## 出售／租赁房屋列表和编辑

顶部仅有“售房”“租赁”两个 Tab，默认“售房”，不提供“全部”Tab。每个 Tab 都提供新增房屋入口；新增表单沿用一次提交创建楼幢、单元、房间与挂牌的能力，可选单独出售、单独租赁或两者都有。小区详情不再承载这个表单。

Tab 下方提供小区名称模糊搜索、片区多选、小区多选。片区与小区同时选择时取交集；小区选项随片区选择缩小，清除片区时保留仍有效的小区选择。表格“楼层”列可按现有楼层筛选，“状态”列可选全部、上架、下架；已有草稿在“全部”中显示为“草稿”，不归入上架或下架。售房、租赁均可按“全部／好价”筛选；售房另可按“全部／急售”筛选。不同筛选条件相互叠加，切换 Tab 时保留通用的搜索和片区／小区条件，专属筛选仅作用于对应 Tab。

每条挂牌新增 `isGoodPrice` 布尔属性；仅售房挂牌可设置 `isUrgentSale` 布尔属性，租赁记录固定为否。现有数据迁移时两个字段默认为否。列表显示对应标识，筛选由挂牌记录而非小区记录决定。

点击出售行打开该条出售房屋的详情／编辑弹窗，点击租赁行打开该条租赁房屋的详情／编辑弹窗；布局参考附件 2，并预填房间位置、价格、面积、户型、装修、状态、默认展示、好价／急售、现有图片。表单底部只有该条记录的一次保存操作，不再把整个小区的“已录入挂牌”嵌入弹窗。替换图片时显示已有缩略图；不选新文件则保留现有图片，详情图总数最多 6 张。编辑使用单次 multipart 请求在数据库事务中保存房间归属、挂牌字段和图片引用，并在失败时清理新写入文件。若同一房间同时挂牌出售和租赁，修改房间位置会同步作用于另一类型的记录，因为两条挂牌共用房间实体；价格、状态、图片和好价／急售仅修改当前挂牌。

## 周边设施列表

“关联小区”列展示小区名称而非 ID 或仅显示数量。多个小区以名称列表展示，过长时折叠并可查看全部。编辑表单的多选项与已选标签也始终显示名称；保存时仍传小区 ID，保持现有数据库关系。

## 接口与数据边界

- `POST /api/admin/communities` 与新增的 `PUT /api/admin/communities/:communityId` 接收完整小区资料和关联设施 ID，一次事务保存。保留既有 ID、房屋、设施关系；编辑坐标或片区时重新执行片区边界校验。
- 批量转移复用现有 `/api/admin/communities/bulk-region`；批量废弃向它提交 `regionId: null`，并清除被废弃小区的热门状态。永久删除继续使用现有删除接口。
- `GET /api/admin/listings` 返回新布尔字段及展示所需的小区、片区和房间信息。新增与编辑接口都维护好价、急售；编辑单条记录提供新的统一保存接口。新增出售且租赁时两条记录共享房间，但各自保存价格与标识。
- 前端列表筛选在已加载的管理数据上完成，保留现有表格分页；后续数据量需要服务端分页时再扩展查询接口。

## 兼容性与验证

- 保留现有片区、小区、房屋、设施数据及其 ID，不迁移或重建业务记录。仅新增挂牌布尔字段默认值；移除整体轮廓写入口和重复的管理菜单／分组。
- 新增后端测试：固定轮廓在空数据库与旧数据库中均返回相同 72 点；无 AOI Key 时仍返回；旧整体轮廓写入接口不可修改固定数据。
- 后端测试：小区一次保存同时更新属性、热门状态和设施关联；批量转移／废弃全有或全无；挂牌编辑不改变另一类型的价格与图片；共用房间的位置同步；布尔字段迁移默认否。
- 前端检查：`/` 和 `/admin` 均无交叉入口按钮；管理树无“启用小区”“热门小区”根节点；新增按钮固定、树滚动、父级路径更新、地图与树选择同步；快速操作、统一小区编辑、房屋 Tab／筛选／编辑弹窗和设施关联名称均按预期工作。
- 两仓分别运行 TypeScript 构建与现有测试，并在浏览器中目视检查 PC 布局。若本机有已运行的后端，调试前确认其加载了当前代码，避免将旧服务响应误认为新实现。
