# 固定横店外轮廓与片区／小区管理改版

日期：2026-09-29
状态：待用户审阅

## 目标与边界

高德 AOI 权限未获批。首页使用用户在“横店总览”中手绘并保存的轮廓作为最终横店外轮廓。管理后台取消独立“横店总览”菜单，在一个页面内维护片区和小区。展示端与管理端不提供相互跳转按钮；开发时仍可手动访问 `/` 与 `/admin`。展示端后续独立开发，本次只处理轮廓来源和入口按钮，不重做其其他交互。

## 固定轮廓数据

方案比较：继续只存在开发机 SQLite 中最省改动，但新 Windows 安装没有轮廓；写成前端常量能离线显示，但会绕开现有地图 API 并在两端产生两份来源；后端仓库保存版本化 JSON，继续由现有读取 API 提供，是本稿采用的方案。

- 来源为本机 `/Users/chengjie/.hd-property-sales/hdmap.sqlite` 的 `overview_boundary` 表中 `id=hengdian` 的记录。已只读核验：72 个 `[经度, 纬度]` 点，更新时间 `2026-09-28T15:21:42.431Z`，坐标范围为经度 120.247453–120.364698、纬度 29.091154–29.21763。
- 实施时将该记录原样导出为后端仓库中的版本化 JSON 数据文件，并校验点数、数值范围及至少三个有效点。该文件成为整体轮廓的唯一运行时数据来源，交付包必须包含它；部署到新 Windows 机器时无需复制开发机 SQLite 才能显示轮廓。
- `GET /api/map/overview-boundary` 继续返回原有 `{ polygon }` 结构，但读取固定文件。移除整体轮廓编辑入口和对应写入接口。既有 SQLite 行保留作历史数据，不在迁移时删除。
- 展示端和管理端都通过上述接口绘制同一轮廓。地图组件停止请求 `/api/map/hengdian-aoi`，不再因 AOI 权限导致轮廓加载失败；地点搜索和路线服务继续使用高德 Web 服务 Key。
- 片区仍是管理员可绘制、编辑、删除的业务边界，与固定横店外轮廓分开维护。

## 管理后台信息结构

主菜单为“片区／小区”“出售／租赁房屋”“周边设施”“字典列表”，默认进入“片区／小区”。删除“横店总览”菜单及其页面入口。管理后台页头删除“打开展示端”按钮；展示端页头删除“打开管理端”按钮。直输 `/admin` 仍允许本机开发访问，后端已有的局域网管理访问限制保持有效。

“片区／小区”页使用左侧树、右侧地图和按操作出现的详情或表单。左侧树顶部固定两个按钮：“新增片区”“新增小区”；按钮不随树内容滚动。树根直接列各片区及“废弃小区站”，不再有“启用小区”和“热门小区”根节点。片区下为小区、楼幢、单元、楼层、房间。热门小区在原小区节点上显示标识，不复制到另一棵树。废弃小区站保留批量移回片区和永久删除的现有规则；废弃小区不显示为地图上的有效点位。

树区域有独立的固定高度与纵向滚动。当节点滚出可视区时，在树滚动区域顶部固定展示首个可见节点的完整父级路径，例如“城南 › 玫瑰星城 › 12 幢”。路径随滚动更新，不遮住新增按钮；点击路径中的父级可定位回该节点。展开、收起和数据刷新后重新计算路径，避免显示失效节点。

## 片区、小区与地图交互

- 点击片区节点或地图面，地图聚焦该片区，并在本页侧栏维护名称、颜色与边界，可删除；新增片区从树顶部按钮进入绘制及保存流程。
- 点击小区节点、地图点位或列表结果，地图定位到该小区并打开已有小区详情弹窗。楼幢到房间的树层级仍用于定位，房屋录入仍使用一次保存表单。
- 新增小区从树顶部按钮进入右侧表单，地图保持可见并可点击回填经纬度；地点搜索、所属片区校验、热门开关、废弃小区规则沿用现有能力。
- 去掉“启用小区”对应的表格内容区。未选中对象时右侧展示完整地图及有效片区、小区点位；选中片区后地图聚焦，选中小区后显示详情。废弃小区站仍用表格执行批量操作。
- 地图的整体固定轮廓始终可见。片区多边形和小区点位叠加在其上；固定轮廓不参与业务编辑。

## 兼容性与验证

- 保留现有片区、小区、房屋、设施数据及其 ID，不迁移或重建业务记录。移除的只是整体轮廓写入口和重复的管理菜单／分组。
- 新增后端测试：固定轮廓在空数据库与旧数据库中均返回相同 72 点；无 AOI Key 时仍返回；旧整体轮廓写入接口不可修改固定数据。
- 前端检查：`/` 和 `/admin` 均无交叉入口按钮；管理树无“启用小区”“热门小区”根节点；新增按钮固定、树滚动、父级路径更新、地图与树选择同步；片区新增和小区新增仍能保存。
- 两仓分别运行 TypeScript 构建与现有测试，并在浏览器中目视检查 PC 布局。若本机有已运行的后端，调试前确认其加载了当前代码，避免将旧服务响应误认为新实现。
